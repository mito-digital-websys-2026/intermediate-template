# 詰まりログ運用ルール（中級）

このリポジトリでの詰まりログの記入・提出ルールです。書き方・コミットのしかたは初級と同じですが、**「判断」欄に書く内容が増えます**。迷ったときはここに戻って確認してください。

## 何を記録するか

**AIの出力を「採用する／しない」と自分で判断した場面**を記録します。解決したかどうかは問いません。

- タイポ・構文エラーの指摘など、判断の余地がない修正は記録しない
- Copilotなどのインライン補完も、**数行以上がまとめて提示され、それをそのまま採用した場合は記録対象**
- 補完されたコードが、なぜ動くか説明できないまま採用された場合は、記録に加えて検証も必須

判断基準は「**あとから『なぜそうしたのか』を問われて答える必要がある場面かどうか**」です。

## どこに書くか

`tsumari-log/weekXX.md` に、`week01.md` に入っている空のフォーマットの書式で追記していきます。週番号はこのリポジトリの中での週です。

| ファイル | 対応する週 |
|---|---|
| `week01.md` | 第4週 |
| `week02.md` | 第5週 |
| `week03.md` | 第6週 |
| `week04.md` | 第7週 |

週が変わったら、前の週のファイルをコピーして新しいファイル（`week02.md` など）を作成し、中身を空のフォーマットに戻してください。

## コミットのしかた

**1件記録するごとに1コミット**が原則です。

```bash
git add tsumari-log/week01.md
git commit -m "log: week1 - 認証方式の選択"
git push
```

週の最後に書く「週まとめ」欄も、別コミットにしてください。

```bash
git commit -m "log: week1 - 週まとめ"
```

まとめて後から書いて一括コミットするのは避けてください。コミット日時が「詰まった直後に記録したか」の参考情報になります。

## 件数の目安

**週3〜5件程度**（目安であり最低件数ではありません。件数ではなく「判断」欄の質を評価します）。1件あたりの記入時間は5分以内が目安です。

## 「判断」欄に何を書くか（中級）

1. **採用したか／しなかったかと、その理由**（初級と同じ）
2. **選ばなかった選択肢と、そちらを選ばなかった理由**（中級で追加）

AIは多くの場合、やり方を複数示します。その中からどれを選び、なぜ他を選ばなかったのかを自分の言葉で書いてください。分量の指定はありません。この欄だけは省略できません。

中級で記録の題材になりやすい場面：

- 認証方式（セッション認証／JWT）を選んだとき。**選んだ方式と理由、選ばなかった方式と理由は必ず記録する**
- 外部キーの `on_delete` を決めたとき
- 業務ルールを、シリアライザのチェックで守るか、DBの制約で守るかを決めたとき
- 件数・票数を、フロントで数えるか、DBで数えるかを決めたとき

## 提出物としての扱い

- 詰まりログは提出物です。`submit-intermediate` タグを打つ前に、その週までの全てのファイルが push 済みであることを確認してください
- 週ごとのファイルが欠けている場合、または「判断」欄が空欄の件が複数ある場合は、該当配点が0点になります
- 評価対象は件数ではなく、「判断」欄の記載有無・質です
- 上級に着手した後の分は、上級リポジトリの `week01.md` に記録します
